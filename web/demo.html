Lore: shared memory with a reviewer in the loop

Governed memory

Definitions, decisions and facts are versioned and scoped by role. A reviewer approves, rejects, expires or forgets them.

Query guard

The model only plans. Code checks every pipeline, adds the user's row filter and removes hidden fields before it runs.

Skills from repetition

Analyses that several people repeat become tested templates that run with the caller's permissions.

Everything audited

Every query and every change to memory or skills is an audit event.

Hidden fields stay hidden, even from the agent

Sam asks for supplier cost. The agent never sees the field, the guard rejects any query that references it, and the refusal is audited.

Live · memory changes the answer

A wrong definition in shared memory spreads to everyone

Net margin v10 · active(revenue − supplier cost) / revenue. Returns are ignored.

With memory, every agent follows it: East's Q3 net margin looks like 36.1%, only a few points behind the other regions.

Live · the correction

A correction becomes a proposal, not a silent edit

  1. Fatima says net margin must subtract returns. The agent answers with her definition and proposes a new version.
  2. The proposal is pending: no agent uses it yet.
  3. In Memory review, the reviewer approves it for every role. The old version is superseded, and both steps are audited.

Live · skills

Repeated analyses become tested skills

  1. Answered questions become episodes: the question pattern, its parameters and its pipeline.
  2. Similar episodes form a cluster. Three episodes from two users make it ready.
  3. A draft skill is tested for replay and permissions, then the reviewer publishes it.
  4. A skill stores logic, never results, so it always runs with the asker's permissions. Approving a new metric version marks skills built on the old one as stale.

Episodes in this demo come from sample activity, labeled as such in the interface.
