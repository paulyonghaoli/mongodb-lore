Lore

An analyst agent for a retail company, with shared memory people govern

Northwind Outfitters: 20 stores, 4 regions. Staff ask business questions in plain language; Lore answers from the sales data in MongoDB Atlas.

How Lore works

Ask a question. The agent queries MongoDB, and the team's knowledge builds up.

  1. 1 · QueryThe agent writes a MongoDB aggregation and runs it, inside your permissions
  2. 2 · SessionEvery question, query and answer is saved in MongoDB
  3. 3 · EpisodeRepeated questions become episodes, then tested skills
  4. 4 · MemoryWhat the team agrees becomes shared memory, used by every agent

Sales data, sessions, episodes and memories all live in one MongoDB Atlas cluster.

Governed end to end, on MongoDB Atlas

  • No leaks between teams: every memory is scoped by role, as an Atlas Vector Search filter.
  • Found by meaning: approved memories are embedded with Voyage AI voyage-4.
  • Safe queries: the agent writes aggregation pipelines; a guard applies each user's permissions.
  • It keeps learning: change streams turn repeated questions into tested, reviewed skills.
  • One cluster: sales data, memories, vectors and the audit log side by side.
